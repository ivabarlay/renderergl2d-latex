\chapter{Conclusiones}\label{cap:conclusiones}

En este proyecto se han desarrollado bibliotecas para el uso de \textit{OpenGL}:
\begin{itemize}
    \item Bibliotecas de configuración de OpenGL.
    \item Creación de geometría.
    \item Animaciones.
    \item Funciones auxiliares de \textit{C}.
    \item Gestión de errores.
\end{itemize}

Todas estas bibliotecas se han utilizado en los programas, a destacar: el programa de animación, que realiza una serie de transformaciones programables a un polígono regular y se renderiza en pantalla. 

Para exprimir y medir las funcionalidades aquí desarrolladas, se han realizado pruebas en las que todas ellas se ven involucradas.
\begin{itemize}
    \item Con \textit{R} y \textit{gnuplot}, se toman cómputos numéricos sobre los datos recogidos y gráficas para visualizarlos con detalle.
    \item Con \textit{Valgrind} se ha analizado el uso de memoria de los programas, además de detectar posibles fugas en la ejecución.
    \item Con \textit{perf} se ha analizado de manera más profunda el uso de \textit{CPU}, detallando número de ciclos, instrucciones por segundo, etc.
\end{itemize}

\subsection{Requisitos iniciales}

Respecto a los requisitos iniciales, se han cumplimentado todos:

\begin{itemize}
    \item Se han creado bibliotecas propias: shaders, polígonos, errores, misceláneo de C y pruebas. Estas bibliotecas abstraen código repetitivo y complejo, a la vez que liberan espacio en el programa principal.

    \item El código está escrito en el idioma inglés, bien comentado, organizado y robusto: gracias a la biblioteca de errores, puede depurarse fácilmente y los fallos no se diluyen en la traza.

    \item Se cumplen los requisitos hardware, pues los programas desarrollados se ejecutan sin prácticamente mínimo de potencia de CPU, RAM o disco; aunque es cierto que se necesita una GPU, o al menos, una gráfica integrada, se asume indispensable para cualquier programa gráfico.

    \item Se han realizado pruebas, extraído resultados de ellas y representado mediante gráficas. Una vez resueltas las pruebas, se han examinado para detectar posibles optimizaciones y, una vez detectadas, retrocedido y aplicado en el código.

    \item Se han creado programas de ejemplo, diseñados como guía de uso para los usuarios que deseen utilizar este proyecto o incluso expandirlo y mejorarlo.

\end{itemize}

\section{Líneas futuras}

Este proyecto sólo es una base para los muchos caminos por los que podría expandirse. A continuación, se enunciarán las posibles líneas futuras que se han contemplado: mejoras de rendimiento, nuevas características, integraciones con otros programas y comparativas.

\begin{itemize}

    \item Mejorar el sistema de animación para permitir geometría tridimensional.

    \item Capacidad de importación de modelos. Se examinó la posibilidad de incorporar \textit{Assimp} con el fin de probar geometría más compleja y diferente.

    \item Algoritmos de triangulación, para transformar geometría compleja en triángulos simples, amigables con la \textit{GPU} y más sencillos de procesar.

    \item Integración con otros programas como extensión y observar ventajas y desventajas. Como caso concreto, \textit{Godot} ofrece una tecnología para interactuar con código \textit{C/C++} llamado \textit{GDExtension} \cite{webGodotGDExtension}, aún en estado experimental; en el caso de ser insuficiente, pueden usarse los módulos personalizados de \textit{C/C++} que también ofrece \textit{Godot} \cite{webGodotCModules}.

    \item Crear comparativas de los tiempos de ejecución respecto a otros programas, como el ya mencionado previamente \textit{Godot}.

    \item Mejora al sistema de animación, permitiendo fácilmente crear caminos distintos para diferentes geometrías y cargar la animación desde un fichero.

    \item Mejora a la biblioteca de \textit{shaders}, abstrayendo aún más las funciones principales, como \textit{initAnimationData}, \textit{initGLData} y \textit{initGLShaders}, incluso permitiendo crear \textit{shaders} básicos sin programar \textit{GLSL}.

\end{itemize}
